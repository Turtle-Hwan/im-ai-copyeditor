## 방법

- 부모 실행기가 실제 `segment.py`로 작업표를 만들고 모델의 작업표에 `reassemble.py --check-punctuation` 실행
- 모델에는 통합 SKILL.md, 공통 약속과 4개 룰북, 원문과 미작성 작업표 제공
- 기대 결과, `must_change`, `absent`, `present`는 모델에 제공하지 않고 실행 후 대조에만 사용
- Sonnet 5 응답을 생성하는 새 Claude CLI 프로세스에서 회차당 14개 문서를 한 번에 처리
- `--safe-mode --tools '' --strict-mcp-config --mcp-config '{"mcpServers":{}}' --disable-slash-commands --no-session-persistence` 적용
- 현재 작업 대화와 전역 메모리 파일 미전달. 독립 문서의 순서는 회차마다 순환
- 장식용 따옴표와 작성자 블록의 편집 옵션은 실행기가 사전에 지정
- 최종 결과는 고정 문자열 검사와 별도로 원문의 주체·대상·수치·가능성과 대조

## 해석 범위

- 개발 중 3회 반복 묶음을 세 차례 실행. 마지막 묶음에서 작업표의 반복 안내문 생략도 요청했으므로 엄밀한 단일 변수 A/B 비교가 아님
- 첫 묶음에서는 표제의 대상을 행위자로 바꾸는 문제도 발견. 주체와 대상 보존을 보완한 뒤 최종 묶음에서는 해당 재현이 없었음
- 일부 입력이 룰북 예시와 겹치는 알려진 문제의 회귀 평가이며, 미지의 문서에 대한 평균 품질 향상을 증명하지 않음
- 자동 검사는 일부 문자열과 구조만 확인. 새로운 숫자·주장 추가나 의미 변화를 모두 판별하는 검사가 아님
- 일반 맞춤법 검사기, 전체 하니스 자율 실행, 보호 예외의 자동 분류 능력을 평가하지 않음
- CLI 내부 보조 모델 호출, 모델 학습과 관리자 정책은 제거하지 않았으며 내부 시스템 프롬프트 전체는 캡처하지 않음
- 자동 테스트 51개 통과와 이 문체 회귀 평가의 미충족 결과를 별도로 보고함
